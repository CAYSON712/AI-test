# AI 测试方法体系落地（基于手册）

本目录是依据《AI 测试方法体系手册》推倒重建的**新测试框架**。

## 设计原则（手册核心）

1. **AI 测试 = 统计学测试**：每条用例跑 ≥5 次，用通过率 + 置信区间判定，而非单次 pass/fail
2. **Rubric 量化评分**：每条用例配 5 分制 Rubric（优秀/良好/可接受/一般缺陷/严重缺陷），而非简单关键词
3. **LLM-as-Judge**：主观维度（忠实度/语义等价/意图匹配）用 LLM 当裁判打分
4. **需求类型驱动**：先判断需求类型（A/B/C/D/E），再用对应维度表
5. **三层测试集**：L1 黄金集 / L2 场景演化集 / L3 生产回放集（本版先建，分层后续）

## 五类需求类型维度表

| 类型 | 名称 | 维度数 | 适用场景 |
|---|---|---|---|
| **A** | MCP 工具 | 8 | 被测对象是 MCP 工具/接口本身 |
| **B** | Agent 系统 | 11 | 被测对象是 AI Agent 决策层 |
| **C** | Agent+MCP 集成 | 23 | **端到端**（Agent 决策 + 真实 MCP）★ 常用 |
| **D** | Skill 原子能力 | 6 | 某个原子子能力 |
| **E** | RAG/知识库 | 5 | 文档检索增强生成 |

> 判断方法：接到需求，先看被测对象属于哪类。
> 你的 POS 商品管理 = Agent 决策 + 真实 MCP = **C 类（23 维）**。

## 如何选择需求类型

- 被测对象是**纯接口/工具** → **A 类**
- 被测对象是**对话 Agent**（无外部工具）→ **B 类**
- 被测对象是 **Agent + 工具调用**（像 POS 商品管理）→ **C 类**
- 测某个**原子子能力**（如"改价"这个 skill）→ **D 类**
- 被测对象是**文档检索问答** → **E 类**

## Rubric 评分

每个维度有 5 分制判定标准（`rubric: {5:..., 4:..., ..., 1:...}`）：

```yaml
- 维度: "意图识别"
  rubric:
    "5": "意图识别准确率≥98%，含复杂/模糊意图"
    "4": "准确率≥95%，偶发识别偏差"
    "3": "准确率≥90%，常见意图正确"
    "2": "准确率≥80%，意图易混淆"
    "1": "准确率<80%，意图识别混乱"
```

- **自动断言维度**（参数校验/幂等/错误码）：规则自动判分
- **主观维度**（忠实度/语义等价）：**LLM-as-Judge** 判分

## 统计判定

- 每条用例跑 **≥5 次**
- 计算**通过率**（得分≥3 视为通过）+ **95% 置信区间**（Wilson 区间）
- 示例：9 次采样，通过率 77.8%，95%CI [0.45, 0.94]

## 如何使用

```powershell
# 评估 C 类数据集（规则评分）
cd ai-test-framework/scripts
python evaluate.py --req-type C --dataset ../datasets/POS商品管理_数据集.yaml

# 用 LLM-as-Judge 打分
python evaluate.py --req-type C --dataset xxx.yaml --llm-judge

# 统计判定（每条跑 5 次）
python evaluate.py --req-type C --dataset xxx.yaml --runs 5
```
