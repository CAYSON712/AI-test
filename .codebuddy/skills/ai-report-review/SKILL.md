# AI 测试报告复盘

## Overview

本 Skill 读取测试执行结果，生成结构化评估报告，分析各维度表现，定位问题，反哺数据集。**不绑定任何具体系统**，只读执行结果 YAML。

- **框架**：`ai-test-framework/`
- **报告入口**：`ai-test-framework/scripts/_08_report.py`
- **报告输出**：`ai-test-framework/report/`

## 前置条件（生成报告前必读）

| 前置条件 | 是否必须 | 说明 |
|---|---|---|
| **执行结果** | ✅ 必须 | 先由「测试执行」skill 产出 `result_<类型>_<时间戳>.yaml`（见该 skill 的「输出」命名规范） |
| **数据集信息** | ⚠️ 建议 | 结果里若缺系统名，报告会显示为空 |

**操作指引**：确认 `ai-test-framework/results/` 下存在对应的 `result_<类型>_<时间戳>.yaml` 后再跑，否则报告无数据可读。
同名会有多份（不同 runs / 维度子集 / 重跑），**取最新的那份**，或显式传路径。

## 报告流程

```powershell
cd ai-test-framework/scripts

# 生成评估报告（读指定结果）
python _08_report.py --result ../results/result_A_20260927.yaml --out ../report/<报告名>.md

# 或只传 result（自动按 评估报告_<时间戳>_<类型>_<数据集名>.md 命名并落到 report/）
python _08_report.py --result ../results/result_A_20260927.yaml
```

> ⚠️ 中文路径/文件名在 PowerShell 下易乱码，建议在 Python 内直接调用
> `from scripts._08_report import generate_report; generate_report(result_path, out_path)`
> 生成；或干脆用 `python _06_run_test.py ... --report` 一步出结果+报告（推荐）。
>
> 报告命名规则（与执行侧一致）：`评估报告_<时间戳>_<类型>_<数据集名>.md`。

## 报告内容

生成的报告包含：
1. **需求类型 + 被测系统 + 采样次数**
2. **维度得分表**（5 分制 Rubric）：平均分、等级、**发布建议**、通过率、采样、95%CI
3. **总体通过率**
4. **问题归属汇总（错误归因）**：三类失分各多少、该提给谁（🔧AI 系统问题→开发 / 📊数据集问题→测试 / 🌐环境问题→运维）
5. **错误类型分布**：错误类型 + 占比 + 主要归因 + 建议修复
6. **问题定位**：低分维度（平均分 < 3）、失败/异常用例，**按归因分组**（开发看 AI 系统问题、测试看数据集问题）
7. **反哺建议**：哪些维度用例偏少，需补充
8. **评分等级标准总览**（手册原文）：5 级标准的「等级 + 标准 + 发布建议」

> **发布建议（新增）**：每个维度得分旁直接标注手册等级对应的发布结论
> （5 优秀=允许发布 / 4 良好=可发布记改进 / 3 可接受=有条件发需跟题 / 2 一般缺陷=不可发需修复 / 1 严重缺陷=阻断发布），团队看报告即可判断"能不能发"，无需查手册。

## 复盘分析角度

| 分析项 | 关注点 |
|---|---|
| **维度得分 + 发布建议** | 哪些维度得分低，是否系统能力缺陷，能否发布 |
| **通过率 + 置信区间** | 结果是否稳定，样本量是否足够 |
| **错误归因（attribution）** | 失分是「数据集问题（→测试修数据）」还是「AI 系统问题（→开发修系统）」还是「环境问题（→运维）」，避免把数据缺陷当系统 bug 误导开发 |
| **错误类型分布** | 操作后校验失败 / 未拦截危险操作 / 工具选错 / 语义不符 / 业务失败 等，哪类最多就优先修哪类 |
| **失败用例（按归因分组）** | 🔧 开发看 AI 系统问题清单、📊 测试看数据集问题清单、🌐 运维看环境问题 |
| **评分来源(via)** | 规则判定 vs LLM判定 vs 默认兜底（via=default 的维度说明未真实判定，需补充用例或校验信息） |
| **反哺** | 低分/用例稀疏维度 → 补充数据集用例 |

## 分层复盘（L1/L2）

数据集分 L1（黄金集）/L2（场景演化）两层，复盘时应区分关注：

| 层 | 掉分含义 | 处理建议 |
|---|---|---|
| **L1** 黄金集 | 核心能力缺陷，问题严重 | 优先排查，直接影响系统可用性 |
| **L2** 场景演化 | 边界/变异覆盖不足，问题较轻 | 补充对应场景用例，不一定改系统 |

> 若执行结果已带层信息，可分层汇总看；当前 report 主要按维度汇总，分层细化可作为后续增强。

## 产出

- 评估报告：`ai-test-framework/report/评估报告_<时间戳>_<类型>_<数据集名>.md`
  （与上文「报告流程」的自动命名一致；例：`评估报告_20260927_203402_D_小韩面无人值守门禁.md`）
- 反哺建议 → 回到「需求分析」skill 补充数据集用例

## 闭环

```
需求分析(生成数据集) → 测试执行(Rubric评分) → 报告复盘(分析反哺) → 需求分析(补充用例) → ...
```
