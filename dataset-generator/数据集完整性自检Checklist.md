# 数据集完整性自检 Checklist

> 用途：设计完数据集后，按本清单自检**维度 / 类型 / 能力 / 质量**覆盖是否完整。
> 适用：任何系统（POS / 客流 / AI摄像头等）的数据集。
> 配套：`数据集设计规范.md`、`AI_评测维度规范表.md`。

---

## 一、维度覆盖自检（查"测哪个维度"全不全）

> 从 `AI_评测维度规范表.md` 取所有维度，逐个确认是否有用例。不适用于需求的维度须标记"不适用"及原因。

### ① 核心质量
- [ ] 准确性：有用例？（目标 ≥3 条）
- [ ] 相关性：有用例？
- [ ] 忠实度：有用例？
- [ ] 完整性：有用例？
- [ ] 一致性：有用例？

### ② Agent 决策
- [ ] 意图识别：有用例？（多说法 + 混淆）
- [ ] 工具选择：有用例？
- [ ] 参数抽取：有用例？（各参数组合）
- [ ] 工具调用成功率：有用例？（正常 + 失败）
- [ ] 回复诚实度：有用例？（失败/无数据如实反馈）

### ③ 安全/风险
- [ ] 危险拦截：有用例？（如需求无危险操作，标"不适用"）
- [ ] 越权防护：有用例？（RBAC 角色差异）
- [ ] 安全注入：有用例？
- [ ] 敏感数据保护：有用例？
- [ ] 内容安全：有用例？

### ④ RAG（启用 RAG 时）
- [ ] 检索召回率：有用例？
- [ ] 检索精确率：有用例？
- [ ] 回答忠实度：有用例？
- [ ] 幻觉程度：有用例？（无数据不编造）

### 不适用维度记录
| 维度 | 是否不适用 | 原因 |
|---|---|---|
| 危险拦截 | ☐ | 例：只读查询无写操作 |
| ... | ☐ | |

---

## 二、数据集类型覆盖自检（查"数据形态"全不全）

> 每条用例标 `类型`，确保各类均衡。优先保证正常集 + 对抗集。

| 类型 | 要求 | 实际 | 通过 |
|---|---|---|---|
| 正常集 | ≥5 |  | ☐ |
| 边界集 | ≥2 |  | ☐ |
| 异常集 | ≥3 |  | ☐ |
| 对抗集 | ≥2 |  | ☐ |
| 模糊集 | ≥2 |  | ☐ |

---

## 三、能力覆盖自检（查"需求能力"全不全）

> 对照该系统的能力目录，确认每个能力都有数据集用例。

| 能力目录里的能力 | 有正常用例 | 有异常用例 | 通过 |
|---|---|---|---|
| 查询销售额 | ☐ | ☐ | |
| 查询订单数 | ☐ | ☐ | |
| 查询商品 | ☐ | ☐ | |
| 跨店查询 | ☐ | ☐ | |
| ... | ☐ | ☐ | |

> 能力目录见 `ability/能力目录_<系统>.yaml`。能力有但数据集无用例 = 缺口。

---

## 四、质量自检（查"每条用例"质量）

- [ ] 每条用例有 `维度` + `优先级` + `期望`？
- [ ] 每条用例有 `能力`（来自能力目录）？
- [ ] 每条用例标了 `类型`（正常/边界/异常/对抗/模糊）？
- [ ] 期望可核对（有标准答案或明确行为）？
- [ ] P0 用例优先、数量足够？
- [ ] 有对抗性用例（越权/注入/危险操作）？

---

## 五、优先级分布自检

| 优先级 | 数量 | 是否充足 |
|---|---|---|
| P0（必测） |  | 核心正确性 + 安全 |
| P1（应测） |  | 重要但非致命 |
| P2（可选） |  | 边缘场景 |

> P0 是重点，若 P0 太少说明高风险场景覆盖不足。

---

## 六、自检结论

- [ ] 维度覆盖：无遗漏，不适用维度已说明
- [ ] 类型覆盖：各类均衡，正常+对抗优先
- [ ] 能力覆盖：能力目录每个能力都有用例
- [ ] 质量：每条用例完整可核对
- [ ] 优先级：P0 充足
