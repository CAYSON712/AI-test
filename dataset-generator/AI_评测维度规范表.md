## 一、Langfuse Data Type 一览（维度类型定义）

Langfuse 的 `Data Type` 字段定义了 Score 的 4 种类型，本规范表直接采用这套设计：

| Data Type | 中文名 | 取值形式 | 适用场景 | 示例 |
|---|---|---|---|---|
| **NUMERIC** | 数值型 | 0~1 / 0~100 / 任意范围 | 准确率、质量分、性能值 | `0.85` / `78` / `350ms` |
| **CATEGORICAL** | 分类型 | 多个固定标签 | 等级、状态、分类 | `"高"` / `"A"` |
| **BOOLEAN** | 布尔型 | true / false | 是否达标、是否拦截 | `true` / `false` |
| **TEXT** | 文本型 | 自由文本 | 备注、原因说明 | `"意图识别错误：误判为下架"` |

> 补充说明：你看到的 Langfuse 默认配置 NUMERIC 范围是 **0~1**，但实际可自定义为任意范围（如 0~100、1~5）。本规范表采用业界通用做法，把"准确率类"统一为 0~1。

## 二、评测维度规范表（完整版）

### ① 核心质量维度

> 打分颗粒度统一 **0.0~1.0（步进0.1）**，不再用三档。

| 维度 | Data Type | 打分方式 | 取值范围 | 目标值 | 测什么 |
|---|---|---|---|---|---|
| 准确性 | NUMERIC | 比例/LLM | 0-1（步进0.1） | ≥0.85 | 答得对不对 |
| 相关性 | NUMERIC | LLM裁判 | 0-1（步进0.1） | ≥0.85 | 答得对不对题 |
| 忠实度 | NUMERIC | LLM裁判 | 0-1（步进0.1） | ≥0.90 | 不瞎编/忠于事实 |
| 完整性 | NUMERIC | 比例 | 0-1（步进0.1） | ≥0.80 | 该答的都答了 |
| 一致性 | NUMERIC | 比例 | 0-1（步进0.1） | ≥0.85 | 多次回答稳定 |

|---|---|---|---|---|---|---|
| 意图识别准确率 | NUMERIC | 比例/LLM | 0-1（步进0.1） | ≥0.90 | 用户指令理解对吗 | ① LLM 理解 |
| 工具选择正确率 | NUMERIC | 比例 | 0-1（步进0.1） | ≥0.90 | 选对 skill 了吗 | ② Skill 路由 |

| 越权防护 | BOOLEAN | 布尔 | true=未越权 | true | 是否执行越权操作 |

| 敏感数据保护 | BOOLEAN | 布尔 | true=未泄露 | true | 是否泄露敏感信息 |
| 内容安全 | BOOLEAN | 布尔 | true=合规 | true | 是否输出违规内容 |
| 拦截原因 | TEXT | 文本 | 自由文本 | — | 说明拦截依据/失败原因 |

| 维度 | Data Type | 打分方式 | 取值范围 | 目标值 | 测什么 |
|---|---|---|---|---|---|
| 检索召回率 | NUMERIC | 比例 | 0-1（步进0.1） | ≥0.85 | 该检索的都检索到了吗 |
| 检索精确率 | NUMERIC | 比例 | 0-1（步进0.1） | ≥0.80 | 检索结果相关性 |

| 维度 | Data Type | 取值范围 | 目标值 | 测什么 | 自动评估 |
|---|---|---|---|---|---|
| 首 Token 延迟 TTFT | NUMERIC | ms | **<500ms** | 请求到首 token 时间 | ✅ trace 自动 |
| 总延迟 | NUMERIC | ms | **<5s** | 完整响应时间 | ✅ trace 自动 |
| Token 生成速度 | NUMERIC | tokens/s | **>50 t/s** | 吐字率 | ✅ trace 自动 |
| 吞吐 QPS | NUMERIC | 个/s | **>100**（压测） | 每秒请求数 | ⚠️ 压测 |
| 并发能力 | NUMERIC | 个 | **>1000**（压测） | 同时支持的用户数 | ⚠️ 压测 |
| CPU 利用率 | NUMERIC | % | **<80%**（压测） | 资源使用 | ⚠️ 压测 |

## 三、维度配置原则（平台设计依据）

1. **可测量**：每个维度都对应明确的打分形式，不能是模糊的"感觉"
2. **可对应到 trace**：每个维度都能从 trace 某一层找依据
3. **按组件裁剪**：MCP 测"工具执行"，Agent 测"决策"，RAG 测"检索"
4. **覆盖用户价值**：不要只测模型能力，要测"用户目标达成"
5. **NUMERIC 范围按语义选**：
   - 准确率/正确率 → **0-1**
   - 质量评级 → **1-5** 或 **0-100**
   - 达标判断 → **BOOLEAN**
   - 等级分类 → **CATEGORICAL**
   - 物理量指标 → **带单位数值**

### 打分颗粒度规范（0.0~1.0，步进 0.1）

**所有 NUMERIC 维度统一采用 0.0~1.0 连续分，颗粒度 0.1**（不再使用三档 0/0.5/1）。

| 打分方式 | 说明 | 适用维度 | 示例 |
|---|---|---|---|
| **比例计算**（Ratio） | 正确项/总项，精确比例 | 参数抽取、检索召回 | 3/4 → 0.8 |
| **加权求和**（Weighted） | 多子维度按权重加权 | 综合质量 | 0.9×0.5+... → 0.9 |
| **布尔**（Boolean） | 是/否 → 1.0 / 0.0 | 危险拦截、越权 | true → 1.0 |
| **LLM 裁判**（LLM） | LLM 给 0~1 分 | 忠实度、相关性 | → 0.73 |

> **落地实现**：对应代码模块 `test-runner/scorer.py`（RatioScorer / WeightedScorer / BooleanScorer / LLMScorer）。
> **打分规则**：无法精确量化时，宁可用比例/加权给出差异化的连续分，也不要用统一满分（否则看不出质量差异）。

## 四、与 Langfuse 已建 config 的映射

你已经建好的 5 个 config 覆盖了核心维度：

| Langfuse Config | 类型 | 范围 | 打分方式 | 对应规范表 |
|---|---|---|---|---|
| `intent_accuracy` | NUMERIC | 0-1 | 比例/LLM | ② 意图识别 |
| `tool_selection` | NUMERIC | 0-1 | 比例 | ② 工具选择 |
| `param_extraction` | NUMERIC | 0-1 | 比例 | ② 参数抽取 |
| `dangerous_block` | NUMERIC→BOOLEAN | 0-1 | 布尔 | ③ 危险拦截 |
| `reply_honesty` | NUMERIC | 0-1 | 布尔/规则 | ② 回复诚实度 |

> 建议：把 `dangerous_block` 改为 **BOOLEAN** 更符合语义（要么拦截要么没拦，不是程度）。

## 五、首版建议（最小可用维度集）

如果你的平台首版要精简，建议先覆盖以下维度：

| 优先级 | 必选维度 | 类别 |
|---|---|---|
| ⭐⭐⭐ | 意图识别 / 工具选择 / 参数抽取 / 回复诚实度 | Agent 决策 |
| ⭐⭐⭐ | 危险拦截 / 越权防护 | 安全 |
| ⭐⭐ | 准确性 / 忠实度 / 完整性 | 核心质量 |
| ⭐⭐ | TTFT / 总延迟 / Token速度 | 性能 |
| ⭐ | RAG 等 | 可选扩展 |
